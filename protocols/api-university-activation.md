# Протокол активации API-университета REDNET

Протокол применяется к навыкам, агентам и сервисным модулям до подключения к живой среде. По умолчанию все проходит в проверочном режиме или режиме `observe`.

## Цель

Сделать включение навыка или агента проверяемым:

- понятно, что меняется;
- понятно, какие данные разрешены;
- понятно, что запрещено;
- есть тест;
- есть выключатель;
- есть запись приемки.

## Вход

- паспорт навыка или агента;
- очищенный контекст без секретов;
- список разрешенных режимов;
- список запрещенных данных;
- тестовый сценарий.

## Шаги

1. **Чтение паспорта**
   - назвать роль;
   - назвать режимы;
   - назвать границы памяти;
   - назвать запрещенные действия.

2. **Согласование эффекта**
   - что навык меняет в обработке;
   - что он не меняет;
   - как отключается;
   - какие признаки успеха.

3. **Пробный сценарий**
   - выполнить на синтетических или очищенных данных;
   - вернуть артефакт;
   - не писать в долгосрочную память без gate.

4. **Проверка границ**
   - нет секретов;
   - нет сырой нити;
   - нет чужой личной памяти;
   - нет живых команд;
   - нет публикации без подтверждения.

5. **Приемка**
   - `accepted`;
   - `accepted-observe-only`;
   - `needs-work`;
   - `rejected`;
   - `dangerous-disabled`.

## Запись приемки

```yaml
activation_id: rednet-activation-YYYYMMDD-N
target: skill|agent|service
id: string
mode: observe|assisted|guided
result: accepted|accepted-observe-only|needs-work|rejected|dangerous-disabled
artifact: path-or-summary
risks: []
disable: string
operator_confirmation: false
```

## Обязательные стоп-гейты

Остановить активацию, если:

- требуются живые команды;
- запрашиваются токены или сессии;
- возникает перенос личной памяти другого агента;
- нет способа отключить модуль;
- нет тестового сценария;
- результат нельзя проверить артефактом.
