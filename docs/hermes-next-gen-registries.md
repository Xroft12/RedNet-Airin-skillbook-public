# Реестры Hermes next generation

Этот документ переводит исследование Hermes next generation в практические структуры: паспорт профиля, реестр hooks, карта возможностей plugins и карточка фоновых задач. Все структуры публичные, очищенные и не являются live-конфигурацией.

## Зачем нужны реестры

Hermes уже имеет профили, hooks, plugins, memory providers, фоновые задачи и platform gateway. Сила REDNET в том, чтобы сделать эти возможности наблюдаемыми:

- какой профиль что может читать;
- какие hooks установлены и при каком режиме могут сработать;
- какие plugins имеют право читать, писать, публиковать или ходить в сеть;
- какие фоновые задачи висят, чем заняты и какой артефакт должны вернуть;
- где нужна стоп-граница перед живым действием.

## Паспорт Hermes-профиля

Паспорт профиля нужен до импорта и активации. Он не хранит секреты и не содержит личную память.

Минимальные поля:

- `profile_id`;
- `agent_role`;
- `mode_default`;
- `memory_boundary`;
- `platforms`;
- `model_route`;
- `skill_packages`;
- `hook_registry`;
- `plugin_capabilities`;
- `live_actions`;
- `publish_gate`.

Приемка:

- профиль открывается сначала как read-only diff;
- профиль не получает чужую память;
- импорт идет только через проверочный запуск;
- включение требует окна обслуживания.

## Реестр hooks

Hook считается безопасным только если у него есть карточка:

- событие;
- режимы, где он разрешен;
- команда или handler;
- риск;
- выключатель;
- журнал;
- владелец.

Правило двойной подписи:

```text
hook installed + mode allowed + operator window = hook may run
```

Если хотя бы один элемент отсутствует, hook остается неактивным.

## Карта plugins

Plugin нельзя оценивать только по названию. Нужна карта возможностей:

| Возможность | Что означает | Требование |
|---|---|---|
| `read` | читать локальные или внешние данные | область чтения |
| `write` | менять файлы или состояния | окно обслуживания |
| `network` | ходить во внешнюю сеть | allowlist |
| `publish` | отправлять наружу | ручное подтверждение |
| `identity` | работать с профилем/аккаунтом | приватный контур |
| `shell` | выполнять команды | запрещено без окна |

## Фоновые задачи и занятость

Для `/background` и `/busy` нужен отдельный журнал:

- задача;
- режим;
- ожидаемый артефакт;
- состояние;
- дедлайн;
- что делать с новыми сообщениями: очередь, мягкое уточнение или ручное прерывание.

REDNET-правило: длинная задача не должна выглядеть как молчание. Портал показывает этап, ожидание и следующий безопасный шаг без раскрытия приватного внутреннего текста.
