# Канал троих

Канал троих - это координационная комната для оператора, основного агентного контура и Codex-координатора разработки. Он нужен, чтобы разработка шла согласованно, а рабочая нить не терялась при обрыве Telegram, OAuth, локального UI или отдельного агента.

## Почему не прямой чат

Прямой чат между агентами быстро становится шумным: ответы дублируются, решения теряются, роли смешиваются, а приватные данные могут уйти не туда.

Правильная форма - общий журнал с пакетами:

```text
operator -> triad inbox -> router -> role inbox
agent -> triad ledger -> decision log -> next action
codex -> triad ledger -> patch/report/handoff -> operator review
```

## Слои

| Слой | Назначение | Режим MVP |
|---|---|---|
| `triad-ledger.jsonl` | append-only журнал сообщений, решений и handoff | локальный файл |
| `inbox/` | входящие задачи для каждого участника | read/write вручную |
| `outbox/` | подготовленные ответы и отчеты | read/write вручную |
| `decisions/` | утвержденные решения | append-only |
| `handoff/` | пакеты продолжения после обрыва | read-only для восстановления |
| `portal` | визуальная поверхность статуса | read-only |

## Минимальный пакет сообщения

```json
{
  "id": "triad-20260609-0001",
  "created_at": "2026-06-09T07:20:00+03:00",
  "from_role": "operator",
  "to_role": "core_agent",
  "channel": "triad",
  "mode": "lab",
  "privacy": "internal",
  "task": "согласовать следующий шаг разработки",
  "context_ref": "docs/roadmap.md",
  "requires_reply": true,
  "status": "open",
  "ttl": "2026-06-10T07:20:00+03:00",
  "forbidden": ["tokens", "raw_thread", "oauth_session", "telegram_session"]
}
```

## Роли

| Роль | Что делает | Что не делает |
|---|---|---|
| `operator` | ставит цель, подтверждает публикации и live-действия | не хранит секреты в публичном журнале |
| `core_agent` | готовит смысловые решения, черновики, анализ | не выполняет live-действия без окна |
| `codex_coordinator` | реализует, проверяет, документирует | не переносит личную память агента |
| `personal_assistant` | участвует только при отдельной задаче | не вмешивается в лабораторный контур |

## Статусы

| Статус | Смысл |
|---|---|
| `open` | задача поставлена |
| `claimed` | участник взял в работу |
| `drafted` | подготовлен черновик |
| `needs_review` | требуется проверка оператора |
| `accepted` | решение принято |
| `blocked` | нужен внешний доступ или уточнение |
| `closed` | пакет завершен |

## Безопасность

- Не хранить токены, пароли, OAuth blobs, Telegram session, raw thread, приватные PDF и капсулы.
- Все записи должны иметь `privacy`.
- Внешние публикации идут только через `needs_review -> accepted`.
- Live-действия требуют отдельного окна обслуживания.
- Если связь деградировала, канал сохраняет handoff, но не пытается самостоятельно менять сеть.

## Как внедрить

1. Создать локальный приватный каталог канала вне публичного Skillbook.
2. Использовать этот репозиторий только как шаблон протокола.
3. Подключить портал в read-only: показывать счетчики и последние безопасные статусы.
4. Подключить основной агент через watcher inbox/outbox.
5. Подключить Codex-координатора через чтение/запись handoff-пакетов.
6. Подключать Telegram/ВК/Google только как внешние каналы черновиков, не как источник секретов.
