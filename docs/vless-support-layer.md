# Слой VLESS

VLESS добавляется в REDNET как модульный сетевой слой, но не как автоматический переключатель маршрута.

## Цель

Дать агентскому контуру еще один управляемый вариант связи на случай деградации Telegram/API/VPN, сохранив главный принцип: сначала наблюдать, проверять и объяснять, потом действовать только через окно обслуживания.

## Режимы

| Режим | Что делает | Что запрещено |
|---|---|---|
| `off` | слой выключен | любые проверки |
| `observe` | отображает наличие профилей и состояние последней проверки | менять маршруты |
| `config-test` | проверяет синтаксис профиля и доступность endpoint без переключения системы | поднимать туннель как основной |
| `manual-window` | оператор вручную включает профиль в окне обслуживания | авто-переключение API/Telegram |
| `incident-hold` | Guardian рекомендует удержать отправку, пока идет деградация | отправлять пакеты через сомнительный маршрут |

## Минимальная модель данных

```json
{
  "technology": "vless",
  "profile_id": "rednet-vless-01",
  "mode": "config-test",
  "last_check": "2026-06-09T00:00:00+03:00",
  "status": "unknown",
  "confidence": 0.0,
  "guardian_recommendation": "observe"
}
```

Публичный Skillbook не хранит реальные VLESS URI, UUID, host, SNI, private keys или маршруты.

## Интеграция

- портал показывает VLESS в разделе `Админка`;
- Control Center должен иметь отдельный блок `VLESS` с кнопками `Проверить`, `Импортировать профиль`, `Отключить слой`;
- Guardian получает только результат проверки и рекомендацию;
- сенсор и нано-узлы могут учитывать VLESS как один из каналов, но не управлять им напрямую.

## Приемка

- профиль можно проверить в dry-run без live-подключения;
- при ошибке VLESS не влияет на Telegram, OAuth, Tailscale и основной VPN;
- кнопки опасных действий отключены до отдельного окна обслуживания;
- в Git нет VLESS URI, UUID и endpoint.
