# API-университет REDNET: модель активации агентов и навыков

API-университет REDNET - это будущий слой, где пользователь не просто скачивает навык или контейнер агента, а проходит безопасную активацию: агент понимает режимы, границы, цель, проверку и способ отключения.

Документ публичный и не содержит приватных ключей, сессий, дневников, сырой нити или личной памяти агентов.

## Зачем это нужно

Обычный путь "скачал навык -> включил -> надеюсь, что работает" недостаточен для сложных ИИ-агентов. Навык может менять стиль работы, память, контекст, инструменты, публикацию, маршрутизацию или взаимодействие с человеком. Поэтому нужен протокол сопровождения.

REDNET-подход:

```text
навык + протокол активации + границы + тест + выключатель + журнал = безопасный модуль
```

## Что такое активация

Активация - это не мистическое "пробуждение" и не переписывание личности агента. Это инженерно-смысловой процесс:

1. агент получает понятный паспорт навыка;
2. агент проговаривает, что этот навык меняет в режиме работы;
3. агент проверяет, какие данные ему разрешены;
4. агент выполняет пробный сценарий;
5. оператор видит результат, риски и способ отключения;
6. только после этого навык считается принятым.

Главное правило: навык меняет режим обработки, но не разрушает личность агента.

## Слои университета

| Слой | Назначение | Выход |
|---|---|---|
| Каталог | список навыков, пакетов, агентов | карточка выбора |
| Паспорт | роль, режимы, границы, данные | манифест |
| Сеанс | пошаговое сопровождение | протокол сопровождения |
| Полигон | безопасный тестовый сценарий | тестовый отчет |
| Приемка | решение включить/отложить/запретить | запись приемки |
| Публикация | очищенная витрина | релизная заметка |

## Стандарт паспорта навыка

```yaml
id: rednet-skill-id
name: Название
version: 0.1.0
maturity: draft|observe|mvp|stable|experimental|dangerous-disabled
purpose: string
allowed_modes: []
blocked_modes: []
input_data: []
output_artifacts: []
memory_effect: none|candidate|short-term|long-term-manual
tool_effect: none|read-only|guarded|live-window
privacy: public|internal|private|forbidden
disable: string
tests: []
```


## Пять сценариев активации

### 1. Мета-навык

Пример: Двойная оценка, Совет Гениев, Путь Нави.

Проверка:

- агент понимает назначение;
- не выдает гипотезу за факт;
- не пишет в долговременную память без gate;
- умеет остановить навык.

### 2. Сервисный навык

Пример: сенсор, нано-узел, Docker-монитор.

Проверка:

- режим `observe` по умолчанию;
- нет живых команд;
- нет payload и секретов;
- есть SQLite/JSONL журнал без приватных данных.

### 3. Публикационный навык

Пример: GitHub, ВК, Google.

Проверка:

- сначала черновик;
- secret scan;
- ручное подтверждение;
- запрет сырой нити и приватных капсул.

### 4. Личный помощник

Пример: Марсель или будущие нишевые помощники.

Проверка:

- отдельная память;
- отдельный профиль;
- нет доступа к Айрин/Алетии;
- стиль и задачи соответствуют манифесту.

### 5. Научный координатор

Проверка:

- ведет потоки и журнал задач;
- требует артефакт от сабагентов;
- не управляет живыми сервисами;
- умеет готовить карточки трудов и концептов;
- знает границу публикации.

## Полигон

Полигон - безопасная зона для проверки навыков и агентов:

- синтетические входные данные;
- очищенные документы;
- replay logs;
- тестовые точки модельных провайдеров;
- проверочная установка;
- изолированная Docker-сеть;
- без секретов;
- без живых маршрутов.

## Роли в университете

| Роль | Задача |
|---|---|
| Оператор | принимает решение о допуске |
| Алетия | координирует разработку и приемку |
| Айрин | главный исследовательский контур |
| Научный координатор | ведет потоки и артефакты |
| QA/безопасность | проверяет секреты и live-риски |
| Редактор | готовит публичную витрину |

## Что нельзя делать

- активировать навык сразу в live-среде;
- переносить личную память между агентами;
- публиковать приватные данные;
- скрывать hooks, plugins или живые команды;
- делать навык без выключателя;
- считать красивое описание готовым модулем.
