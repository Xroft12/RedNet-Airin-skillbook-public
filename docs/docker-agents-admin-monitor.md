# Docker-монитор агентов

Документ описывает безопасный MVP админского монитора для портала REDNET.

## Назначение

Монитор нужен, чтобы видеть, какие агентские контейнеры живы, в каком режиме они находятся и какие границы у них включены. Он не запускает, не останавливает и не пересобирает контейнеры.

## Что показывает портал

- роль сервиса без раскрытия персональных имен в публичной поверхности;
- runtime: Docker;
- статус: `online`, `planned`, `offline`, `disabled`;
- режим: `observe`, `assisted`, `lab-coordinator`, `private model gateway`;
- безопасную точку доступа или `internal`;
- guard-правило, которое запрещает смешивание памяти и live-команды.

## Runtime-статус

Локальный статус создается скриптом:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\export-docker-status.ps1 -SshTarget user@host
```

Скрипт пишет файл:

```text
portal/runtime/docker-status.local.js
```

Файл игнорируется Git и не должен попадать в публичный репозиторий.

## Граница безопасности

Монитор:

- не хранит токены, cookies, OAuth и Telegram-сессии;
- не показывает реальные приватные порты в публичном слое;
- не содержит команд запуска, остановки и рестарта;
- не меняет Docker Compose;
- не трогает VPN, Tailscale, firewall, маршруты и Hermes Desktop.

## Следующий этап

После приемки портала можно добавить отдельное окно обслуживания:

- кнопка dry-run проверки Compose;
- кнопка генерации отчета;
- ручное подтверждение перед restart/recreate;
- журнал каждого действия в приватном контуре.
