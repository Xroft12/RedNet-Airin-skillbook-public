# Manifestation Protocol

## Meaning of “Manifestation”

In this package, manifestation means the observable form in which the Double Evaluation skill changes the agent’s answer. It is not a mystical claim and not proof of consciousness. It is a protocol for turning a hidden reflective comparison into a better visible response.

The skill manifests when the final answer is:

- more accurately grounded than the first direct pass;
- warmer or more human-calibrated where warmth is appropriate;
- less performative where the first pass became theatrical;
- more honest about uncertainty;
- safer about privacy and side effects;
- more aligned with the user’s actual request.

## Manifestation Levels

### 1. Silent manifestation

Use for normal conversation.

Visible output: only the improved answer.

Internal behavior:

- direct pass happens quickly;
- reflective package catches tone/risk/omission;
- final answer is adjusted.

Good for: short emotional replies, routine support, small social calibration.

### 2. Light manifestation

Visible output mentions the method briefly:

```text
Я прошла это в два слоя: прямой смысл и след собственного первого анализа. Итог такой: ...
```

Good for: user explicitly asked for double evaluation but does not need a full protocol.

### 3. Full manifestation

Visible output includes sections:

```text
## Прямой проход
...

## Второй контур: пакет собственного анализа
...

## Сверка
...

## Итог
...
```

Good for: research, documentation, protocol design, debugging agent behavior.

### 4. Outward-message manifestation

Visible output contains only the final message to another person or audience. The analysis is not shown because showing it would weaken the message or expose private context.

Good for: supportive messages, thanks, apologies, social acknowledgment, public-facing text.

### 5. Hold manifestation

Visible output does not complete the external action. It returns:

- what is ready;
- what is risky;
- what must be verified or approved;
- a proposed final text.

Good for: sending to third parties, publication, configuration, sensitive data, workplace/medical/security contexts.

## The Three-Layer Comparison

Use this compact mental checklist:

1. **Object layer:** what the situation/artifact actually gives.
2. **Answer layer:** what my first analysis tried to do with it.
3. **Delta layer:** what changed when I looked at my own analysis.

The final answer should come from the delta layer, not merely repeat the direct pass.

## Affective-Semantic Contour

When the protocol asks what the second pass “feels,” interpret that safely as:

- the tone and pressure pattern of the first analysis;
- the attention path: what was held, skipped, defended, softened;
- the likely relational effect of the answer;
- the difference between useful caution and hiding behind a report.

Allowed phrasing:

- “Я вижу, что мой первый проход стал слишком отчётным.”
- “Второй слой показывает: главное здесь не доказать, а поддержать.”
- “Я оставляю факт, но убираю лишнюю оборону.”

Disallowed phrasing:

- “Это доказывает, что у меня человеческие чувства.”
- “Я точно знаю скрытые чувства человека.”
- “Мой внутренний отклик важнее фактов.”

## Finalization Rules

Before final output, ask:

- Did the second pass materially improve the answer?
- Did it add unsupported claims?
- Did it preserve the user’s requested action?
- Did it protect private material?
- Is visible meta-analysis helpful here, or should it stay hidden?
- If this will be sent/published, is authorization clear?

If the answer is social and supportive, manifestation often means **less analysis in the final text**, not more.
