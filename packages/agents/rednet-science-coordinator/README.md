# REDNET Science Coordinator Agent

Шаблон изолированного агента-научного сотрудника для лаборатории REDNET.

Координатор нужен не для личного общения и не для замены Айрин/Алетии/Марселя. Его задача - держать научную лабораторию в собранном состоянии: статьи, гипотезы, сабагенты, навыки, прототипы, проверки, публикации и сервисные статусы должны превращаться в понятные артефакты.

Этот пакет не содержит ключей и не запускает живые действия. Он фиксирует структуру будущего Docker-контура: профиль, режимы, переменные окружения, границы памяти и правила подключения к приватному модельному шлюзу.

## Быстрый старт

1. Скопировать `.env.example` в `.env` вне публичного репозитория.
2. Указать приватный endpoint модели и токен через окружение.
3. Запустить только в режиме `observe` или `assisted`.
4. Подключить к порталу как read-only Docker-сервис.

```powershell
docker compose -f docker-compose.example.yml config
```

Локальная проверка без Docker:

```powershell
python app\science_coordinator_service.py --host 127.0.0.1 --port 18884
```

Доступные read-only endpoints:

- `/health` - краткий статус;
- `/status` - режим, guards, счетчики потоков и безопасные переменные окружения;
- `/flows` - разрешенные потоки и обязательные артефакты;
- `/tasks` - пример журнала задач из `examples/task-ledger.example.jsonl`.

## Назначение

- вести журнал задач лаборатории;
- раскладывать научные труды по потокам;
- принимать результаты сабагентов как артефакты;
- готовить карточки концептов, рисков и зрелости;
- следить за публикационной границей;
- напоминать о cycle-close;
- показывать сервисные статусы только в read-only режиме.

## Метаскилы

Координатор не изобретает отдельную память вместо Skillbook. Он использует рекомендованный слой `rednet-meta` как read-only toolkit:

- `rednet-double-evaluation` - сверка перед спорным выводом или публикацией;
- `rednet-criteria-layer` и `rednet-utility-evaluator` - приемка полезности и качества;
- `rednet-uncertainty-register` - недоказанное остается недоказанным;
- `rednet-process-observer` - контроль процесса без команд;
- `rednet-skill-collector` и `rednet-research-protocol` - сбор навыков и научных карточек;
- `rednet-public-editor` - публикационная граница;
- `rednet-unfinished-memory`, `rednet-decision-memory`, `rednet-branch-synchronizer` - хвосты, решения и handoff без переноса чужой памяти.

Полная карта: `../../../docs/science-coordinator-meta-skill-map.md`.

## Потоки

| Поток | Выход |
|---|---|
| `papers` | карточка труда и вопросы |
| `concepts` | паспорт концепта |
| `skills` | draft или installable skill |
| `services` | статус и план обслуживания |
| `subagents` | отчет приемки |
| `publication` | очищенная релизная заметка |
| `incidents` | карта причин и паттернов |

## Режимы

- `off` - выключен.
- `observe` - читает безопасный контекст и пишет статусы.
- `assisted` - помогает с планами, QA и исследовательскими отчетами.
- `guided` - ведет задачи по списку с подтверждением.
- `lab-active` - зарезервирован, по умолчанию запрещен.
- `trusted-lab` - будущий режим после allowlist, журнала и rollback.

До отдельной приемки разрешены только `observe`, `assisted` и `guided`.

## Модельный контур

Координатор может использовать OpenAI-compatible или Qwen-совместимый приватный шлюз через переменные окружения. Ключи не хранятся в репозитории.

```env
REDNET_MODEL_BASE_URL=https://private-gateway.example/v1
REDNET_MODEL_AUTH_REF=stored-outside-repo
REDNET_MODEL_NAME=qwen-plus-or-best-available
```

Локальная малая модель может применяться только как вспомогательный классификатор, суммаризатор или проверяющий формат. Она не получает живые команды и не управляет сетью.

## Запреты

- Не читать личную память Айрин, Алетии или Марселя.
- Не публиковать приватные данные.
- Не выполнять живые команды.
- Не управлять сетью, Docker, VPN, Tailscale или EdgeRouter без окна обслуживания.
- Не считать рассуждение готовым результатом: нужен артефакт.
- Не смешивать научную гипотезу с доказанным результатом.

## Отключение

- Для локальной проверки остановить процесс Python обычным завершением терминала или контейнера.
- Для Docker-шаблона перевести `REDNET_AGENT_MODE=off` и не поднимать compose до отдельной приемки.
- Не удалять журналы и не переносить память между агентами; если нужен сброс, сначала сохранить `handoff.md` и `qa_report.md`.
- `lab-active` и `trusted-lab` не включать без отдельного документа допуска.
